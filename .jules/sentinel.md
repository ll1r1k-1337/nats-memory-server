## 2024-05-18 - Path Traversal in File Downloads
**Vulnerability:** The `downloadFile` utility extracts the destination filename directly from the `Content-Disposition` header using a naive split operation. Since this value is ultimately controlled by the external server (or intercepted requests), a malicious server could provide a filename like `../../etc/passwd` or `C:\Windows\System32\cmd.exe` allowing arbitrary files to be overwritten on the host system.
**Learning:** Naive parsing of HTTP headers, especially when related to file paths, often neglects dangerous payload characters. Even standard HTTP utilities like `make-fetch-happen` don't automatically sanitize the `Content-Disposition` values. Furthermore, `Content-Disposition` filenames might contain surrounding quotes, making a simple `.split('filename=')` fragile and insecure.
**Prevention:** Always use a robust regex to parse the filename, removing surrounding quotes. Critically, process the resulting extracted string through `path.basename()` before joining it with the target directory path. This reliably strips out all directory components (like `/` or `../`), ensuring the file is safely written strictly inside the intended directory.
