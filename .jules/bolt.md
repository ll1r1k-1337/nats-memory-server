## 2024-03-09 - Optimize high-volume child process streams
**Learning:** For high-volume log streams (like `stderr` in `child_process.spawn`), continuously calling `.toString()` on every chunk and checking string contents can create significant CPU and memory overhead. Using a state flag (e.g. `isReady`) and `Buffer.includes()` on raw binary chunks avoids expensive string allocations once the desired state is met. Additionally, if you stop processing the stream, you must call `.resume()` to prevent the child process from blocking due to a full pipe.
**Action:** When searching for a specific string in a child process stream, use `isReady` flags and early returns, check binary chunks with `Buffer.isBuffer(chunk) ? chunk.includes('text') : chunk.toString().includes('text')`, and ensure unconsumed streams are `.resume()`d.
