## 2024-05-18 - [Optimize High-Volume Node.js Stream Parsing]
**Learning:** Checking string conversions `.toString()` on every chunk of a high-volume stream (like a spawned child process stderr) just to find a "ready" state causes a massive CPU overhead. Once the state is detected, continuing to parse the stream for that same state is wasteful. Also, calling `.unref()` on the child process could cause the parent process to hang on shutdown when the child process output stream is unconsumed due to lacking listeners (e.g. `verbose = false`).
**Action:** When searching for specific markers in binary streams, prefer using `Buffer.includes()` on the raw chunks. Once the marker is found, use a boolean flag (e.g., `isReady`) to short-circuit further expensive checks. Also, be careful to keep processing streams if necessary, but skip unnecessary string allocations, and verify that stream unref calls do not interfere with shutdown sequences.
